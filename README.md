# Software-Based Virtual Router

**Problem Statement ID:** SWFW_5S_07

## About the Project

I am developing a software-based virtual router using my Linux laptop. The idea is to use the laptop as a wireless access point so that another device, such as a mobile phone, can connect to it and access the internet.

I used Linux networking tools to configure the access point, assign IP addresses, resolve DNS requests, forward packets and apply firewall rules.

## Features Implemented

- Wireless access point using hostapd.
- DHCP service using dnsmasq.
- DNS forwarding and caching.
- IP forwarding and NAT.
- Firewall rules using iptables.
- DNS and firewall activity logging.
- Bash script for starting the router.
- Java-based command-line interface (integration still needs verification).

## Technologies Used

- Ubuntu / Linux
- Java
- Bash scripting
- hostapd
- dnsmasq
- iproute2
- iptables

## Project Structure

- `config/` – DHCP, DNS, firewall, logging and access point configurations.
- `scripts/` – Router startup and shutdown scripts.
- `phases/` – Work and testing carried out in different phases.
- `docs/` – Project flow diagram.
- `routerCLI.java` – Java command-line interface.

## Requirements

- A Linux system with root/sudo access.
- hostapd, dnsmasq, iptables and iproute2 installed.
- A wireless adapter that supports access point mode and simultaneous AP and managed operation.
- The current scripts use `wlp2s0` as the upstream interface and assume a 2.4 GHz upstream Wi-Fi connection.

## Configuration and Running

1. Clone or download this repository.
2. Copy `config/hostapd/hostapd.conf.example` to `config/hostapd/hostapd.conf`.
3. Edit the hostapd configuration with your own Wi-Fi SSID and password.
4. Check the interface names in the scripts and firewall configuration.
5. Start the router:

```bash
sudo bash scripts/start-router.sh
```

The shutdown script is available at:

```bash
sudo bash scripts/stop-router.sh
```

**Note:** The shutdown script has not yet been fully tested. Use these scripts only in a test environment and review their effects on your existing network configuration first.

Do not upload your actual `hostapd.conf` file or Wi-Fi password to GitHub.

## Testing

I tested the access point by connecting an external mobile phone to it. The phone received an IP address through DHCP and was able to access `example.com`.

I also checked DNS requests and firewall log entries generated by the connected device.

The configuration syntax for the combined DHCP and DNS configuration was checked successfully. The complete startup process still needs a final verification after the latest configuration change.

## Current Limitations

- The project currently depends on the wireless interface names used on my laptop.
- The upstream Wi-Fi and virtual access point share one wireless adapter, so changes in the upstream connection may interrupt the access point.
- Direct testing of blocked firewall traffic is pending.
- The shutdown script needs further testing.
- Complete integration of the Java CLI with the router scripts is not yet verified.

## Project Status

The access point, DHCP, DNS, packet forwarding, NAT and logging have been configured and tested with an external device. Firewall rules and startup configuration have also been checked.

Further testing and integration work are still required.
