# Phase 5 – Firewall Configuration

## What I did

In this phase, I configured firewall rules using Linux `iptables` to control the traffic entering and leaving my virtual router.

The main purpose was to allow necessary network communication while restricting other incoming traffic from connected clients.

## 1. Creating firewall chains

I created two custom chains:

- `VR_INPUT` – Handles incoming traffic from the virtual access point.
- `VR_FORWARD` – Controls traffic forwarded between the client network and the upstream network.

## 2. Configuring input rules

I configured the firewall to:

- Allow established connections.
- Allow DHCP requests on UDP port 67.
- Allow DNS requests on UDP and TCP port 53.
- Allow ICMP echo requests (ping).
- Drop other incoming traffic from `ap0`.

## 3. Configuring forwarding and NAT

I allowed traffic from `ap0` to the upstream interface `wlp2s0`.

Returning traffic is allowed when it belongs to an established or related connection.

I also configured NAT masquerading through `wlp2s0` so that devices using the private router network can access external networks.

## 4. Configuration files

I maintained the firewall rules in:

- `config/firewall/firewall-rules.v4`
- `config/logging/firewall-logging.v4`

The second configuration also includes the firewall logging chain.

## 5. Testing

I checked the firewall configuration syntax using:


sudo iptables-restore --test < config/logging/firewall-logging.v4


I loaded the rules and checked the custom chains and packet counters using `iptables`.

The rules were successfully loaded.

I also observed firewall log entries generated by traffic from the connected device.

## Observation

The firewall rules were loaded successfully, and firewall activity was recorded in the system log.

The actual blocking behaviour of individual unwanted connections still needs a separate direct test.

## Result

Basic firewall filtering, packet forwarding rules and NAT masquerading were configured using `iptables`. Firewall logging was also integrated to observe network traffic.
